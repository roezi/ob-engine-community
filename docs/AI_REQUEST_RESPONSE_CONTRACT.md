# AI Request / Response Contract

This document defines normalized `AI_Request` and `AI_Response` contracts for OBE. It is documentation only and does not implement runtime classes.

## AI_Request

| Field | Required now | Future-only | Purpose |
| --- | --- | --- | --- |
| `request_id` | No | No | Unique request correlation ID generated by the AI Engine when absent. |
| `task_type` | Yes | No | One documented AI task type. |
| `input` | Yes | No | User/source input after policy-appropriate redaction or summarization. |
| `instructions` | Yes | No | Public-safe task instructions assembled from prompt contracts. |
| `model_profile` | Yes | No | Internal profile such as `fast`, `balanced`, `deep`, or `background`. |
| `model` | No | No | Provider model chosen from settings/profile resolution. |
| `reasoning_effort` | Yes | No | Task-driven effort such as `low`, `medium`, or `high`. |
| `verbosity` | Yes | No | Task-driven output verbosity such as `low`, `medium`, or `high`. |
| `output_schema` | No | No | Structured output schema contract name and version. |
| `tools` | No | Yes | Future tool declarations. Disabled in Community v0.5. |
| `tool_choice` | No | Yes | Future tool selection policy. Omitted or `none` by default. |
| `store` | No | No | Provider storage preference. Default `false` or configurable. |
| `metadata` | Yes | No | Redacted request metadata for tracing and Activity integration. |
| `safety_identifier` | No | Yes | Future provider safety identifier. Must not expose private user data. |
| `prompt_cache_key` | No | Yes | Future cache key for prompt reuse. Must not include secrets/private payloads. |
| `background` | No | Yes | Future long-running/background mode flag. Default `false`. |
| `source_context` | No | No | Redacted source preview/summary context. |
| `library_context` | No | No | Related Library item IDs, versions, and summaries. |
| `redaction_policy` | No | No | Redaction policy to apply before logging, UI, or provider mapping. |
| `created_by` | No | No | User ID or system actor metadata. |
| `created_at` | No | No | Creation timestamp. |

Required now: `task_type`, `input`, `instructions`, `model_profile`, `reasoning_effort`, `verbosity`, and `metadata`.

Future-only: `tools`, `tool_choice`, `prompt_cache_key`, `background`, and `safety_identifier`.

## AI_Response

| Field | Purpose |
| --- | --- |
| `request_id` | Correlates response with request. |
| `provider` | Provider ID such as `openai`, `gemini`, or custom provider ID. |
| `model` | Provider model used. |
| `status` | One of `completed`, `failed`, `refused`, `partial`, or `cancelled`. |
| `output_text` | Safe normalized text output. |
| `output_json` | Parsed structured output for schema-driven workflows. |
| `refusal` | Safe refusal reason, if any. |
| `finish_reason` | Normalized finish reason when provider supplies one. |
| `usage` | Normalized usage record. |
| `error` | Normalized `AI_Error` when status is failed/refused/partial. |
| `raw_response_redacted` | Redacted provider response for diagnostics, never raw secrets. |
| `library_item_id` | Library item created/updated later through Library Layer. |
| `activity_id` | Activity event ID for audit trail. |
| `created_at` | Response timestamp. |

Statuses:

- `completed`
- `failed`
- `refused`
- `partial`
- `cancelled`

Rules:

- Raw provider response must not be passed directly to UI.
- Raw API keys must never appear in response.
- Raw provider errors must be mapped to safe user-facing errors.
- `output_json` must be used for structured workflows when available.
